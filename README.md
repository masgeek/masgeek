## 👨‍💻 About me

Senior software engineer with 14+ years designing and building production systems: backend services, APIs, enterprise integrations, mobile apps, data platforms and infrastructure.

My strongest area is the space between application code and real-world systems: integrating services, designing APIs, moving data reliably between systems, processing async workloads, automating workflows and keeping production platforms observable and maintainable.

I work across PHP/Laravel, .NET, Java/Spring, Python, PostgreSQL, SQL Server, Docker and Linux, from application code to architecture and production infrastructure.

More recently I've been applying LLMs to practical engineering and domain problems: structured outputs, validation, workflow automation and integrating AI into existing systems rather than treating it as a standalone experiment.

## 🧭 What I do

### Backend & platform engineering

- Production REST APIs and backend services
- Service architecture, distributed systems and system-to-system integrations
- Queue-based and asynchronous processing, background jobs, workflow orchestration
- Payment and transactional integrations
- Data pipelines and structured data processing
- Authentication and API security
- Performance, reliability and production troubleshooting

### Systems integration

A big part of my work has been connecting systems that were never designed to work together: third-party APIs, payment systems, enterprise apps, messaging and queues, databases, webhooks and callbacks, scheduled jobs, and the data transformation and validation between them.

I enjoy the unglamorous problems: reliability, retries, idempotency, failure handling, monitoring and operational visibility.

### 🤖 AI & automation

About a year of hands-on AI engineering, focused on integrating AI into existing software and business workflows. Practical rather than model-centric:

- LLM API integration, structured outputs, prompt design and evaluation
- Data extraction, transformation and validation of AI-generated data
- LLMs wired into downstream APIs and databases
- Local LLM experimentation and AI-assisted developer tooling

Example: turning farmer training field guides into structured, validated data for downstream systems, combining LLM output with conventional validation and workflow processing.

### 🏗️ Architecture

I care about systems beyond getting an endpoint to return `200 OK`: service boundaries, API contracts, retries, idempotency, database design, caching, connection pooling, observability, failure isolation, containerisation and operational simplicity.

For small and medium systems I prefer boring technology that's easy to operate over distributed infrastructure for its own sake. When complexity is justified, I'm comfortable reasoning about service boundaries, async processing, integration patterns and operational trade-offs.

## 🧩 Engineering philosophy

**Simple → Observable → Reliable → Maintainable → Scalable**

Not every system needs microservices, Kafka or Kubernetes. A well-built Laravel app with queues, Redis, PostgreSQL, Docker and good observability often beats a pile of unnecessary services.
